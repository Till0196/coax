# 内蔵カードリーダー（`coax card` / PC/SCソケット）

チューナーの中には、カードスロットを内蔵しているデバイスがあります。
どれもCCIDリーダーではなく、ブリッジ独自の経路でカードと通信するので、OSからはカードリーダーとして認識されません。
`coaxd`は、このスロットを次の2つの方法で使えるようにします。

| 方法 | 用途 |
| --- | --- |
| `coax card` | 手動での確認。カードの有無、ATRの取得、任意のAPDUの送信 |
| `coax pcsc` | 既存のPC/SCアプリケーションからの利用。PC/SCソケット（`pcscd.comm`）を作成するので、アプリケーションは接続先を変えるだけで使えます |

カードにアクセスするのは`coaxd`だけで、`coax card`もHTTPで`coaxd`に要求します。
実装は[winscard.md](winscard.md)にあります。

## 搭載デバイス

内蔵スロットを使えるのは、USBデバイスを直接制御するバックエンドだけです。
`dvb`や`bda`のようにOSのドライバーを経由するバックエンドでは、スロットへのアクセスがドライバー内に閉じているので使えません。

| バックエンド | 製品 | 経路 | 受け渡しの単位 |
| --- | --- | --- | --- |
| `px4` | PX-W3U4 / W3PE4 / W3PE5、PX-Q3U4 / Q3PE4 / Q3PE5 | IT930xのUART | 生のバイト列 |
| `pxmlt` | PX-MLT5U / MLT5PE / MLT8PE、ISDB6014、DTV02A-5TS-P | IT930xのUART | 同上 |
| `isdb2056` | DTV02A-1T1S-U、ISDB2056N、PX-M1UR | IT930xのUART | 同上 |
| `s1ur` | PX-S1UR、DTV03A-1TU | IT930xのUART | 同上 |
| `px3` | PX-S3U / S3U2 / W3U2 / W3U3 / W3U3 V2 | ASIE5606（ブリッジのI2C上）| T=1ブロック |
| `fsusb2` | KTV-FSUSB2 | EM2874のカードインタフェース | T=1ブロック |
| `fsusb2i` | KTV-FSMINI、KTV-FSUSB2/V3（K1212〜）| IT9175内蔵のカードインタフェース | T=1ブロック |
| `us3pout` | US-3POUT | EM287xのカードインタフェース | T=1ブロック |
| `cech-zd1j` | Sony CECH-ZD1 J | MB86H47A内蔵のカードインタフェース（ブリッジのレジスタ越し）| T=1ブロック |

デバイスを開くのにファームウェアが必要なデバイスは、カードを使うときにもファームウェアが必要です。
`px4`系と`fsusb2i`がこれにあたります（置き場所は[firmware.md](../setup/firmware.md)）。
`px3`も同様ですが、ファームウェアが書き込まれていないデバイスを検出すると書き込みを行い、USBデバイスとして再接続されるのを待ってから開きます（[px3.md](../boards/px3.md)）。
`cech-zd1j`はファームウェアが不要ですが、電源投入後に別のドライバーが操作したMB86H47Aは開けません。
その場合はいったん抜いて挿し直してください（[cech-zd1j.md](../boards/cech-zd1j.md)）。

### 一覧に表示されるが、カード無しと応答するもの

`coax card --list`はデバイスを開きません。
スロットの有無は電源を入れないと分からず、一覧表示のたびにすべてのデバイスの電源を入れることはできないためです。
そのため一覧はバックエンドごとの想定で作成し、スロットが無いことは接続時に判明します。

1台が複数のUSBデバイスとして認識される製品では、この差が一覧に現れます。

- PX-MLT8PE（`pxmlt`）は2台として認識されますが、スロットがあるのは5チューナー側だけです。3チューナー側も一覧に表示され、カード無しと応答します。
- Q3系（`px4`のPX-Q3U4 / Q3PE4 / Q3PE5）は4チューナーずつ2台として認識されます。スロットは1台に1つで、接続されているのは片方だけです。2台はシリアル番号の15桁目が1か2かで区別でき、スロットがあるのは1の側です。

Q3系でシリアル番号が15桁の数字でない場合や、15桁目が1でも2でもない場合は、どちらか判別できません。
その場合は両方をスロットとして一覧に出し、スロットの無い側はカード無しと応答します。
いずれの場合も2台とも一覧に表示されるので、[`--reader`](#coax-cardの使い方)で名指しする必要があります。

## `coax card`の使い方

```sh
# スロットの一覧（カードにはアクセスしない）
coax card --list

# カードの有無だけを確認する（カードはリセットしない）
coax card --status

# カードをリセットしてATRを表示する
coax card

# ATRに続けて任意のコマンドAPDUを送る（複数指定可）
coax card "90 30 00 00 00" 9032000000

# スロットが複数あるときは名前で選ぶ
coax card --reader "PLEX PX-W3U4 series Smart Card Reader (ID: 0123456789ABCDEF)"
```

| フラグ | 効果 |
| --- | --- |
| `--list` | スロットを一覧表示します。カードにはアクセスしません |
| `--status` | カードの有無だけを確認します。リセットしません |
| `--reader <名前>` | 使うスロットを指定します |
| `--json` | 表の代わりにJSONで出力します |

APDUは16進数で指定します。
区切り文字として無視するのは、空白、`:`、`-`、`_`の4つだけです。

スロットが1つならそれを使います。
2つ以上あるときは`--reader`が必須で、指定しないとエラーになります。
カードが入っているスロットを自動で選ぶことはしません。
意図しないカードにアクセスしないためです。

## PC/SCソケットの使い方

`coax pcsc`がソケットを作成します。
pcsc-liteのクライアントライブラリとpcscdの間のプロトコルをそのまま実装しているので、既存のPC/SCアプリケーションをそのまま接続できます。

```sh
coax pcsc
# serving PC/SC on /run/user/1000/coaxd/pcscd.comm
# point clients at it with PCSCLITE_CSOCK_NAME=/run/user/1000/coaxd/pcscd.comm
```

アプリケーション側は、クライアントライブラリが参照する環境変数で接続先を変えるだけです。

```sh
PCSCLITE_CSOCK_NAME=/run/user/1000/coaxd/pcscd.comm example-pcsc-app ...
```

インストールや既存ファイルの置き換えは不要です。
pcscdが動いていても競合しません。pcscdは自身のソケットとリーダーをそのまま使い続けます。
pcscdのパス（`/run/pcscd/pcscd.comm`）を既定にしていないのはこのためです。

場所は`--socket`で変えられます。
既定は`coaxd`のソケットと同じディレクトリの`pcscd.comm`で、パーミッションは`0600`です。

アプリケーションはソケットが存在する前提で接続するので、常に使う場合は`coax pcsc --idle 0`をsystemdやlaunchdで常駐させてください。

### 1回だけ使うなら`coax tune --pcsc`

`coax tune`に`--pcsc`を付けると、`coax pcsc`も一緒に起動します。
`coaxd`と同じく必要なときだけ起動するので、常駐させずに1行で外部のプログラムに通せます。

```sh
coax tune --ch 27 --pcsc |
  PCSCLITE_CSOCK_NAME="$XDG_RUNTIME_DIR/coaxd/pcscd.comm" ts-filter
```

この方法で起動した`coax pcsc`は`--idle 1m`で動くので、接続の無い状態が続くと終了します。

### OSごとの接続方法

| OS | 接続先 | アプリケーションの改造 |
| --- | --- | --- |
| Linux、BSD | `coax pcsc`のソケット | 不要。`PCSCLITE_CSOCK_NAME`で指定するだけ |
| Windows | `BonDriver_coax`に付いている`WinSCard.dll`（DLLが直接`coaxd`にHTTPで接続するので、`coax pcsc`は不要です）。または`coax pcsc`のソケット（Windowsにも`AF_UNIX`があります）| 不要 |
| macOS | Homebrewのpcsc-liteから`coax pcsc`のソケットへ | 不要 |

Windowsで`coax pcsc`が不要なのは、`WinSCard.dll`がアプリケーションのプロセス内で動くためです。
別のプロセスが常駐している前提にはできないので、BonDriverと同じく直接`coaxd`に接続します（同じフォルダの`winscard.ini`の`[coax] Host`を読みます）。
pcsc-liteをリンクしたWindowsアプリケーションには、`coax pcsc`も使えます。

## リーダー名

`<ベンダー> <モデル> Smart Card Reader (ID: <16桁>)`という形です。
IDは、デバイスを識別する値のFNV-1aハッシュです。
ハッシュには、バックエンド名と、次のうち最初に当てはまるものを入れます。

| 条件 | ハッシュに入れるもの |
| --- | --- |
| シリアル番号とポート経路の両方が読める | シリアル番号とポート経路 |
| シリアル番号だけが読める | シリアル番号 |
| ポート経路だけが読める | ポート経路 |
| どちらも読めない | デバイスのセレクタと`VVVV:PPPP`のUSB ID |

上の3つは抜き差ししても変わらない値なので、同じポートに挿している限り名前は変わりません。
最後のものだけは、環境によって変わることがあります。
