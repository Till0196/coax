# PLEX PX-S3U / S3U2 / W3U2 / W3U3 / W3U3 V2（バックエンド`px3`）

| | |
| --- | --- |
| バックエンド | `px3` |
| 対応OS | Linux / Windows / macOS（直接USB）|
| 伝送方式 | ISDB-T、ISDB-S |
| ファームウェア | 要（`asv5211-firmware.bin`。[firmware.md](../setup/firmware.md)）|

ASV52xxのUSBブリッジ、TC90522復調器、地上側のFC0012またはNM13x、衛星側のチューナーを直接制御します。
5製品は2つの世代に分かれ、両世代で同じなのはブリッジと復調器だけです。
1つのASV52xxのUSBデバイスが衛星（index 0）と地上（index 1）の2本のチューナーを持ちます。
PX-W3U2、PX-W3U3、PX-W3U3 V2にはASV52xxが2つあり、1つの筐体が2つのUSBデバイスとして見えます。

OSごとの準備は[os.md](../setup/os.md)にあります。
WindowsでWinUSBを割り当てる`.inf`は[`driver/windows/px3-winusb.inf`](../../driver/windows/px3-winusb.inf)にあります。
Windowsでは、通常のIDとコールドID（後述）の両方にWinUSBを割り当てます。
Linuxにはこれらのデバイスに対応するカーネルドライバーが事実上ありません（メインラインには無く、CentOS 6向けのバイナリモジュールがあるだけです）。

## Windows のベンダー製 BDA ドライバーで使う場合

ベンダー製 BDA ドライバーを割り当てたまま、`bda` バックエンドでも使えます。
対象は PX-S3U、S3U2、W3U2、W3U3、W3U3 V2 と、PCIe の PX-W3PE、W3PE V2、Q3PE です。
この経路のファームウェア読み込みとチップの初期化はベンダー製 BDA ドライバーが行います。

INIT、47番での TSID 指定、TS の同期バイト復元、カード送受信は共通のプロトコルを使います。
S3U は1つの BDA フィルターで地上と衛星を切り替え、その他の機種は公開されたフィルターごとの放送方式に従います。

カードはベンダー製ドライバーの Tuner0 を起点に扱います。
W3PE、W3PE V2、Q3PE は、同じ PCI デバイス内のカード状態を Tuner0 に集約します。
USB の複数ブリッジ機では、各ブリッジの候補がベンダー製ドライバーの機器情報によって同じカード状態へ転送されることがあります。
W3U2、W3U3、W3U3 V2 は筐体にカードスロットが1つあり、RF 制御のブリッジ数とは別に扱います。
PC/SC では USB トポロジーから同じ筐体の候補をまとめ、リーダーを1つだけ表示します。これは `px3` と `bda` の両方に適用します。
筐体を特定できない候補は個別に残し、同じ筐体と分かるカード操作は直列化します。
カードへのコマンド長は世代名でなく、ドライバーが返す機能フラグに従います。

### ベンダー製 BDA ドライバーの LNA の設定

ベンダー製 BDA ドライバーは、レジストリの LNA の設定を当てて選局します。
PX-W3U3 V2 では、選局のたびに読み直すことを確かめています。
キーは`HKEY_LOCAL_MACHINE\SOFTWARE\ASICEN\LNASetting`の下にあり、機種ごとに形が違います。

PX-S3U・S3U2・W3U2・W3U3・W3PE・W3PE V2 は、地上側に自動調整の設定があります。

| 機種 | キー |
| --- | --- |
| PX-S3U | `0B06_0001\ISDBT` |
| PX-S3U2 | `0B06_0003\ISDBT` |
| PX-W3U2 | `0B06_0004\ISDBT` |
| PX-W3U3 | `0B06_0005\ISDBT` |
| PX-W3PE | `0B06_0001_PE\ISDBT` |
| PX-W3PE V2 | `0B06_0003_PE\ISDBT` |

```text
LNA_AUTO_CTRL       0: 手動  1: 自動（既定）
External_LNA_ON     手動のとき  0: 外付け LNA を使わない（既定）  1: 使う
Internal_LNA_Level  手動のとき  0: 最小 〜 23: 最大（既定 23）
```

値が無いときは、3つとも 0（手動、外付け LNA を使わない、内蔵 LNA は最小）として読みます。

PX-W3U3 V2（`0B06_0006`）と PX-Q3PE（`0B06_0002_PE`）には、自動調整の設定はありません。
代わりに、チューナーごとの利得の表があります。

表にあるループスルーは、チューナーが受けたアンテナの信号を、中で別のチューナーへ分けて送る仕組みです。
ループスルーの利得は、このとき送る信号の強さです。
`T<n>Gain0`と`S<n>Gain2`は、チューナーが同一ハード内の別のチューナーへ分けて送る信号の強さを設定します。
大きすぎると同一チューナーのもう片方の側の入力が強すぎ、小さすぎると弱すぎになります。

```text
ISDBT
  T_GlobalGain0   地上の LNA  0: 切  1: 入（既定、V2 だけ）
  T<n>Gain0       ループスルーの利得  1: 最大（既定）  2: 高  3: 中  4: 低
ISDBS
  S_GlobalGain0   衛星の LNA  0: 切  1: 入（既定、V2 だけ）
  S<n>Gain0       増幅器の出力  0x0: 15dB  0x1: 18dB  0x2: 18dB  0x3: 21dB  0x6: 24dB  0x7: 27dB  0x0E: 30dB  0x0F: 33dB
  S<n>Gain1       LNA の利得  0x0: 7dB  0x1: 10dB  0x2: 13dB  0x3: 18dB  0x4: -11dB
  S<n>Gain2       ループスルーの利得  0x0: -8dB  0x1: -10dB  0x2: -14dB  0x3: -16dB
```

`<n>`は、V2 では 0 と 1、Q3PE では 0〜3 です。
衛星の既定値は、V2 では`S0`・`S1`とも Gain0 が 0、Gain1 が 3、Gain2 が 0 です。
Q3PE では`S0`が 3・4・1、`S1`が 6・3・3、`S2`と`S3`が 3・3・3 です。

ある程度の信号強度がある場合、既定の利得では入力が強すぎて衛星の C/N が下がることがあります。
そのときは`S<n>Gain1`を下げるか、V2 では`S_GlobalGain0`を 0 にして LNA を切ると、C/N がよくなることがあります。
ループスルーで信号を受けているチューナーは、送る側の`S<n>Gain2`で減らすと C/N がよくなることがあります。

衛星の LNB の給電は、`HKEY_LOCAL_MACHINE\SOFTWARE\ASICEN\LNBPower`の下の機種のキーの`LNBONOFF`です（0: 切（既定）、1: 入）。
キーは地上と同じ機種名で、PX-W3U2 は`0B06_0004`、W3U3 は`0B06_0005`、W3U3 V2 は`0B06_0006`、W3PE は`0B06_0001_PE`、W3PE V2 は`0B06_0003_PE`、Q3PE は`0B06_0002_PE`です。
PX-S3U（`0B06_0001`）と PX-S3U2（`0B06_0003`）のドライバーも`LNBONOFF`を読みますが、その値で給電を切り替えません。

### PX-W3U3 V2のループスルー

PX-W3U3 V2の2組目は、地上も衛星も、1組目のチューナーからループスルーで信号を受けます。

ベンダー製 BDA ドライバーでは、2組目のブリッジのフィルターから I²C に届かず、1組目のブリッジのフィルターを通して制御します。
このため、`bda`は2組目を開くとき、1組目の同じ方式のフィルターも開いたままにします。

ベンダー製 BDA ドライバーは、1組目を選局すると、ループスルーの利得を設定します。
地上は`0B06_0006\ISDBT`の`T0Gain0`、衛星は`0B06_0006\ISDBS`の`S0Gain2`です。
値は選局のたびに読み直されるので、変えたあとに coaxd やドライバーを起こし直す必要はありません。

電波品質が落ちるかどうかは、入ってくる電波の強さによると考えられます。
落ちるときは、3（中）か4（低）にすると直ることがあります。
下げすぎると、電波強度の弱い局では不安定になります。

衛星も、1組目の`S0Gain2`を変えると2組目の C/N が変わります。

PX-Q3PE にも同じループスルーの設定がありますが、同じことが起きるかは確かめていません。

`px3`で直接動かすときは、`LOOP_THROUGH`（`--loop-through`）がこの設定に当たります。
`T<n>Gain0`と`S<n>Gain2`と同じく、チューナーが同一ハード内の別のチューナーへ分けて送る信号の強さを設定します。
2組目の入力を下げたいときは、1組目のチャンネルで指定します（[channel-files.md](../reference/channel-files.md#loop_through)）。

### PX-W3U2／PX-W3U3の2つのブリッジ

無印のPX-W3U2／PX-W3U3も地上2本・衛星2本です。
各ブリッジが自身の地上1本・衛星1本の制御とストリームを受け持ち、どちらも復調器のアドレスは`0x30` / `0x32`です。
2ブリッジであること自体はV2の判別条件にはなりません。

どちらかを最初に開くと、同じハブ配下の両ブリッジを取得し、それぞれのGPIOと復調器・チューナーを初期化します。
もう片方を開いたときは初期化済みの筐体を共有し、最後の利用者が閉じるまで両ブリッジを保持します。
両方のブリッジを開ける状態にしておく必要があります。

起動時はGPIOの初期状態を設定し、復調器を準備してからFC0012へアクセスします。
もう一方のブリッジの再列挙に影響するGPIO `0x40`は、この初期状態設定では保持します。

### PX-W3U3 V2の2つのブリッジ

PX-W3U3 V2も地上2本・衛星2本で、2つのブリッジがそれぞれ地上1本・衛星1本のストリームを受け持ちます。
ただし、チップを操作するのは片方のブリッジだけです。
各ブリッジは、ベンダーコマンド`0x0c`で読める情報の最後のバイトの上位2ビットに、筐体の中での位置を持っています。
位置0のブリッジが、GPIOでの電源投入と、両方の組の復調ICとチューナーのI2Cをすべて受け持ちます。
位置1のブリッジは自分のGPIOもI2Cも使わず、2組目のストリームを流すだけです。

そのため、位置1のブリッジを開くと、同じハブの下にある位置0のブリッジも内部で開き、2組目（`0x24` / `0x26`）はそちらを通して操作します。
2つが同時に開かれても、USBデバイスは1回だけ開いて共有します。
LNB給電と基板上の増幅器の線も位置0のブリッジにあり、2組で共有しています。

同じ筐体のもう一方のUSBデバイスを指名するときは、`--device`に列挙番号か`bus:address`を渡します。

無印とV2のどちらも、ボード側でTC90522へモデルに応じた設定を行ってから地上チューナーを初期化します。
AGCと再取得はTC90522のレジスタで制御します。
地上側の`b8`はFC0012搭載機で`ff`、V2で`c0`です。
FC0012搭載機では地上側の`47=00`・`75=02`を含む初期設定と、衛星側の初期設定を行います。
地上選局後は`01=40`で再取得し、`23=4c`でAGCを再開します。`75=02`を保持し、`71/72`は書き換えません。
V2では地上選局後に`71=01`・`72=24`・`75=02`を設定します。
S3U2／W3U2／W3U3では初期化の最後と地上・衛星の選局後に地上側の`0f=34`を設定します。
S3Uは地上選局後に`0x30:0f=14`、衛星選局後に`0x34:0f=3c`を設定します。
S3U2は地上RF初期化後と衛星復調器初期化後に、地上チューナーの`10=00→10→00`を送ります。

## ファームウェア

ASV52xxブリッジ用の`asv5211-firmware.bin`（16384バイト）が必要です。
入手先は[firmware.md](../setup/firmware.md)にあります。
PLEX公式のLinuxドライバーのパッケージを`fwextract`に渡すと取り出せます。
PLEXのサイトでは404になっているため、Internet Archiveから取得できます（手順は[firmware.md](../setup/firmware.md)にあります）。
Windows版のドライバーのパッケージからは取り出せません。
ファームウェアはOSに関係なく同じなので、Windowsで使うときもLinux版から取り出したものを置いてください。
TC90522とチューナーICにはファームウェアは要りません。

### 自動で送り込む

これらのデバイスは、接続した直後はコールドID（`1738:5211`または`1738:5216`）で見えます。
`coaxd`は一覧を作る前にコールドIDの機器を探してファームウェアを転送し、`px3`として再列挙されるのを待ちます。
ファームウェアをフォルダに置いておけば、ほかの操作は不要です。
`--backend px3`で直接開くときも、`px3`の機器が無ければ、コールドIDの機器にファームウェアを送ってから開きます。

コールドのままの機器は一覧に出ません。
ファームウェアが見つからないときは、`coaxd`のログに一度だけそのことが出ます。
手で送り込むときは`coaxd load-asv52xx-firmware --firmware <イメージ>`を使います。

### ファームウェアの判別

ブートROMは、4回のベンダーコントロール転送でファームウェアを受け取ったあと、ホストが指定したアドレスへジャンプします。
このアドレスはファームウェアのビルドごとに違い、間違えると機器が応答しなくなります（挿し直しが必要です）。
そのため、渡されたイメージのSHA-256から既知の4つのビルドのどれかを判別して、アドレスを選びます。
`--firmware-index`が要るのは、表に無いイメージだけです。
送り込む前に、サイズが0x4000であることと、転送しない範囲（`0x0c00`–`0x2000`、`0x2400`–`0x2800`）が0であることを確認し、合わなければ機器に転送せずに中止します。

| SHA-256 | 入手元 | ジャンプアドレス |
| --- | --- | --- |
| `b45d5102…` | PLEX Linuxドライバーの`loader.ko`（2013-01）| `0x5399` |
| `5db39fac…` | PLEX Windows BDAドライバーのローダーが使うもの（2009-12）| `0x55d6` |
| `f4848c8c…` | PLEX Windows PBDAドライバーのローダーが使うもの（2009-09）| `0x55d8` |
| `d134890d…` | Windowsのローダーに含まれるが使われないもの | `0x515f` |

## 定義ファイル

共通の書式は[channel-files.md](../reference/channel-files.md)にあります。
ここでは`px3`だけの分を書きます。

ISDB-Sでは衛星IF周波数を書きます。
`STREAM_ID`は、12未満をTMCCの相対スロット番号、12以上をTSIDとして扱い、省略すると相対スロット0を選びます。
ISDB-S3には対応していません。

衛星側は、QM1D1B0004が対応する950000〜2150000kHzのどの中間周波数でも選局できます。
BSの12波とCS-110の12波だけでなく、その間の周波数も、分周比、バンドテーブル、ローパスフィルターの式から計算して設定します。

### `GAIN`

`GAIN`が効くのは、PX-S3U／S3U2／W3U2／W3U3の地上側だけです。
FC0012の低雑音増幅器はレジスタ`0x13`の24段で、−9.9dB〜+19.7dBです。
PX-S3U／S3U2は起動時に最大の段を使います。
PX-W3U2／W3U3は初期ロック後に利得を調整します。`GAIN`を指定した場合は、その段を維持します。
`+7dB`のように書くと、いちばん近い段を選びます。

PX-W3U3 V2は入切だけです。
地上と衛星それぞれの基板上の増幅器を、ブリッジのGPIOで入れたり切ったりします。
チップが利得の値を公表していないので、`min`／`max`だけを受け付け、`dB`での指定は受け付けません。
起動時は両方とも入っています。
FC0012搭載機の衛星側には利得設定がありません。

### `LOOP_THROUGH`

`LOOP_THROUGH`は、選局するチューナー自身のループスルー出力の強さです。
`max`、`high`、`mid`、`low`のどれかを書きます（[channel-files.md](../reference/channel-files.md#loop_through)）。

| 機種 | チューナー | 段 | 省略したとき |
| --- | --- | --- | --- |
| PX-W3U3 V2 | 地上（NM120）、衛星（TDA20142） | 4段 | 最大 |
| PX-S3U／S3U2／W3U2／W3U3 | 地上（FC0012） | 入切のみ。`low`は切、それ以外は入 | 切 |
| PX-S3U／S3U2／W3U2／W3U3 | 衛星（QM1D1B0004） | なし。指定しても無視します | - |

PX-W3U3 V2の2組目は、地上も衛星も1組目からループスルーで受けます。
2組目の入力が強すぎるときは、1組目のチャンネルに`LOOP_THROUGH`を書いて下げます。
書いた段は、1組目を選局したときに当てます（[PX-W3U3 V2のループスルー](#px-w3u3-v2のループスルー)）。

### LNB給電

PX-W3U2・W3U3・W3U3 V2のLNB給電は、GPIOで入れたり切ったりするだけで、電圧は選べません。
`low`と`high`はどちらも「給電する」、`off`は「給電しない」です（[tuner-host.md](../reference/tuner-host.md)）。
この3機種は筐体の衛星の入力が1つで、2組で共有しています。
V2は位置0のブリッジのGPIOだけで給電します。
W3U2・W3U3は、どちらの組が給電を求めても、両方のブリッジのGPIOで入れ、どちらも使わなくなったら両方で切ります。
このため、`/tuners`の衛星の`controls`では、LNB給電の`shared`を`card`（筐体で共有）としています。

PX-S3U、PX-S3U2は、ACアダプターをつないでいる間は常に給電し、ソフトウェアからは切り替えられません。LNB給電が不要な場合は、ACアダプターを接続せずに利用してください。
このため、`px3`はPX-S3U・S3U2の給電を操作しません。
`/tuners`の衛星の`controls`にLNB給電は含まれず、`lnb_power`（`VOLTAGE`）を指定したチャンネルは`409 unsupported`（`lnb_supply`）で断ります。
電源を入れる手順の中で動かすGPIO 0x20は、選局では触りません。

## 信号測定

C/Nは、TC90522の生のカウンターを地上・衛星それぞれの変換式に通した値です。
信号強度は出しません。
地上側のFC0012はdBmを返せますが、衛星側のQM1D1B0004には読み出す手段が無く、片方だけ値が出るのを避けて、両方とも出していません。

## 制限事項

- V2ではカードICのリセットが地上側の増幅器と同じGPIOバンクを使うため、選局のたびに最後に指定された増幅器の状態を書き直します。
