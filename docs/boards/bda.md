# Windows BDA（バックエンド`bda`）

| | |
| --- | --- |
| バックエンド | `bda` |
| 対応OS | Windows専用 |
| 伝送方式 | ドライバーによる（一覧の`deliveries`は空欄＝不明）|
| ファームウェア | 不要。メーカー製の64ビットBDAドライバーが必要 |

Windowsのメーカー製BDAドライバーを通してチューナーを使います。
BDA Network Providerと、デバイスのチューナー／キャプチャフィルターを探索して接続し、DVBv5の定義からTune Requestを組み立てます。

BDAのチューナーも、USBチューナーやLinux DVBと同じく`coaxd`が管理し、同じ一覧に並びます。
名前は`bda:<デバイスパスのハッシュ>:0`で、`coax list`が製品名と一緒に表示します。
チューナーを指名するときは、この名前を`--tuner`に渡します。

## 前提条件

チューナーメーカーの64ビットBDAドライバーが入っていて、そのフィルターが標準のNetwork Providerにつながることが必要です。
製品専用の制御DLLを必要とするデバイスは対象外です。

## 使用例

```powershell
.\coax.exe list

.\coax.exe scan `
  --tuner "bda:3f2a9c1d80b45e67:0" `
  --output scan.json `
  .\channels.conf
```

## 対応する伝送方式

ISDB-T、ISDB-S/S3、DVB-T/T2、DVB-C/J.83 Annex B、DVB-S/S2の標準Tune Requestを生成します。

受信できる方式をBDAに尋ねる方法が無いので、一覧の`deliveries`は空欄になります。
空欄は「受信できない」ではなく「分からない」という意味で、方式を指定した要求でも候補に入ります。

## 定義ファイル

共通の書式は[channel-files.md](../reference/channel-files.md)のとおりです。
このバックエンド固有の追加項目はありません。

`FREQUENCY`は、DVBv5でふつうのHz単位か、衛星の中間周波数の定義で使われるkHz単位かを判別し、BDAが受け取るkHz単位に変換します。
ISDB-S/S3の`STREAM_ID`はTSIDとして渡します。

## LNBfと22kHzトーン

BDAでは、ほかのバックエンドと役割が逆になります。
ほかのバックエンドは`coaxd`が中間周波数まで計算してチューナーに渡します。
BDAでは、アンテナに付いているLNBfの情報をドライバーに設定し、ダウンリンク周波数を渡します。
局部発振周波数を引くのはドライバーなので、どちらのバンドかを判断して22kHzトーンを出すのもドライバーです。

BDAには、トーンを直接出すプロパティがありません。
トーンは、LNBfの情報からドライバーが決めるものです。
そのため、`LNB`キー（または`lnbf`パラメーター）でLNBfを指定したチャンネルでは、`IDVBSTuningSpace`に次の3つを設定します。

| 設定先 | 内容 |
| --- | --- |
| `Put_LowOscillator` | 低いほうの局部発振周波数（kHz）|
| `Put_HighOscillator` | 高いほう。1つしか持たないLNBfでは同じ値を入れます（ドライバーは「切り替えるバンドが無い」と解釈します）|
| `Put_LNBSwitch` | バンドの切替周波数（kHz）。1つしか持たないLNBfでは0 |

そのうえで、locatorの`CarrierFrequency`にはダウンリンク周波数を渡します。
`coaxd`の中で一度中間周波数に直したものを、ここで元に戻しています。

LNBfを指定しないチャンネルでは、周波数をそのまま渡し、LNBfの情報も設定しません。
中間周波数をそのまま書いた日本のISDB-Sの定義ファイルはこちらです。

LNBfの指定方法は[channel-files.md](../reference/channel-files.md)にあります。

## DiSEqC

対応しています。
ドライバーが公開する`IBDA_DiseqCommand`ノードを探し、チャンネルが指定したメッセージをそのまま渡します。
メッセージの中身はLinuxの経路と同じで、規格が定めるバイト列そのものです。
違うのは送り方だけです。

渡すのはメッセージだけです。
その前後の電圧とトーンはドライバーが決めるもので、そのためのバンドと偏波はチューニングスペースで伝えてあります。
BDAには、同軸の電圧やトーンを直接操作する手段がありません。

トーンバーストと繰り返し回数は、ドライバーが対応している場合だけ設定します。
このインタフェースは6つのプロパティからなりますが、ドライバーが全部を持っているとは限りません。
実際、次のように一部しか持たないドライバーがあります。

| | `DDTuner.sys` | `tbs6812.sys` |
| --- | --- | --- |
| 0 ENABLE | ○ | ○ |
| 1 LNB_SOURCE | ○ | ○ |
| 2 USETONEBURST | − | ○ |
| 3 REPEATS | − | ○ |
| 4 SEND | ○ | ○ |
| 5 RESPONSE | − | ○ |

無いプロパティは飛ばします。
設定する値（バーストなし、繰り返しなし）は、そのプロパティを持たないドライバーの既定の動作と同じです。
持っていないことを失敗にすると、Digital Devicesのチューナーボードでは一度もメッセージを送れなくなります。

トーンバーストは使いません。
バーストはDiSEqCより前の2入力スイッチに入力を選ばせるためのもので、そういうスイッチにはメッセージのほうが通じません。
両方を1回でまとめて送るドライバーに両方を指定すると、スイッチは別々の2つの指示を受け取ることになります。

送信後は待機します。
ドライバーは送信を受け付けた時点で成功を返し、実際に送るのはそのあとです。
送り終わったかを問い合わせる手段が無いので、同軸に信号が出ている時間だけ待ちます。
1バイトが22kHzのキーイングで22ビット、約13.5msで、これに規格が定める間隔を足した時間です。

## ロック判定

ロックしたかどうかは、届いたTSの量で判断します。
届いたバイト数がしきい値を超え、受信を始めてからの待ち時間も過ぎていれば`locked`です。
スキャンで読むテーブルを取りこぼさないよう、受信開始から一定時間はバッファに保持します。
ロック状態を正しく返さないBDAドライバーがあるので、この形にしています。

そのうえで、`IBDA_SignalStatistics::Get_SignalLocked`に対応するドライバーでは、その値を優先します。
届いた量からの推測より、ドライバーのフラグのほうが確かだからです。

## 信号測定

`IBDA_SignalStatistics`から読めるものを読みます。
この部分はまだ実機で確かめていません。
値の尺度はドライバーによって異なり、このノードを公開しないドライバーもあります。

C/Nは取れないので、代わりにドライバーが決めた品質（0〜100%）を表示します。
信号強度は、ノードが返した値をそのまま出します。

## グラフを持つプロセス

`coaxd`は、BDAのグラフを自分では持たず、起動した別のプロセス（`coaxd bda-host`）に持たせます。
`bda`、`tbs`、`dd`の各バックエンドと、ベンダードライバーで使う`t230`（[t230.md](t230.md#windowsでベンダードライバーのまま使う)）が対象です。

ベンダードライバーの中には、グラフを止めずにプロセスが終わると、Windowsが停止したり（[dd.md](dd.md#受信中にグラフのプロセスが強制終了されるとブルースクリーンになる)）、チューナーを抜き差しするまで使えなくなったりするものがあります。
`bda-host`は`coaxd`とのつながりが切れると、正しい順序でグラフを止めてから終了するので、`coaxd`が強制終了されても、こうした状態になりません。

`bda-host`は最初にBDAのチューナーを開くときに起動し、`coaxd`が終わると終了します。
診断ログは`coaxd`のログ（`--log`、`COAXD_LOG`）に出ます。

## 制限事項

- LNB給電の入切はできません。標準Network ProviderのTune Requestには給電を切る手段が無く、給電はドライバーが決めます。そのため`lnb_power=off`（`VOLTAGE=off`）は`unsupported`のエラーにします。`off`を指定するのは通常外部から給電している場合なので、意図せず給電しないようにするためです。電圧そのものは偏波から決まるので、`low`/`high`は見ません（[channel-files.md](../reference/channel-files.md#バックエンドごとの対応)）。
