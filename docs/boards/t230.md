# MyGica T230（バックエンド`t230`）

| | |
| --- | --- |
| バックエンド | `t230` |
| 対応OS | Linux / Windows / macOS（直接USB）、Windows（ベンダードライバー経由）|
| 伝送方式 | DVB-T、DVB-T2、ITU-T J.83 Annex A / B / C（DVB-C、ISDB-C）|
| ファームウェア | 要（Si2168用とチューナー用。[firmware.md](../setup/firmware.md)）|

DVBSkyのUSBブリッジ、Silicon LabsのSi2168復調器、Si2141またはSi2157チューナーを、バルク転送で直接制御します。
Windowsでベンダードライバーを入れたままでも使えます（[下記](#windowsでベンダードライバーのまま使う)）。
搭載しているチューナーと、Si2168にTS_CLK_MANUALの手順が必要かどうかは、製品IDで判別します。

## 対応製品

| 製品 | VID:PID | チューナー | チューナー本数 | 伝送方式 |
| --- | --- | --- | --- | --- |
| MyGica T230 | `0572:c688` | Si2157（IFポート1）| 1 | DVB-T、DVB-T2、DVB-C、DVB-C/ANNEX_B、DVB-C/ANNEX_C、ISDB-C |
| MyGica T230C | `0572:c689` | Si2141 | 1 | 同上 |
| MyGica T230C Lite | `0572:c699` | Si2141 | 1 | 同上 |
| MyGica T230A | `0572:689a` | Si2141 | 1 | 同上 |
| MyGica T230C2 | `0572:c68a` | Si2141 | 1 | 同上 |
| MyGica T230C2 Lite | `0572:c69a` | Si2141 | 1 | 同上 |

ITU-T J.83のAnnex AとAnnex C（`DVB-C`、`DVB-C/ANNEX_C`、`ISDB-C`のどれで書いてもよい）は、Si2168の1つのDVB-Cモードで受信します。
2つの違いはロールオフだけで、ISDB-CはAnnex Cそのものです。
トレリス符号化を使う別の方式のAnnex B（`DVB-C/ANNEX_B`）は、同じチップが別に持つMCNSモードで受信します。

## ファームウェア

Si2168の復調器のファームウェアが必要です。
チップの版を見て、`dvb-demod-si2168-<a20|a30|b40|d60>-01.fw`のうち合うものを自動で選びます。

チューナーのファームウェアも同じフォルダに置いてください。
まずチップが報告したROM IDから`dvb_driver_si21<41|57>_rom<ROM IDの16進2桁>.fw`を探し、無ければ`dvb-tuner-si2141-a10-01.fw`／`dvb-tuner-si2157-a30-01.fw`を使います。
入手先と置き場所は[firmware.md](../setup/firmware.md)にあります。

`dvb_driver_si2141_rom60.fw`と`rom61.fw`は、どの公開ファームウェア集にも無く、MyGica／Geniatechが配布しているドライバーのパッケージにだけ入っています。
無くても`dvb-tuner-si2141-a10-01.fw`が使われるので、普通はこの2つを用意する必要はありません。

チューナーのファームウェアが見つからなくても、チップのROMのままで起動を試みます。
ROMのままで動作する個体がある可能性と、動作しなかった場合に原因を示すためです。
起動できなかったときは、探したフォルダとファイル名をエラーに出します。

```
initialize Si2141: Si2141 command 0x01: the tuner raised its error bit (status 0xc0);
no firmware was found in ./firmware, and this tuner will not start from its ROM
(tried dvb_driver_si2141_rom60.fw, dvb-tuner-si2141-a10-01.fw)
```

## 定義ファイル

共通の書式は[channel-files.md](../reference/channel-files.md)にあります。
ここでは`t230`だけの分を書きます。

- DVB-T／DVB-T2では`FREQUENCY`と`BANDWIDTH_HZ`が必要です。`STREAM_ID`はPLP IDとして読みます。
- J.83 Annex A／Cでは`SYMBOL_RATE`が必要で、`BANDWIDTH_HZ`は省略できます。`MODULATION`は復調器に渡さず自動判別に任せるので、書かなくても、`QAM/AUTO`でも構いません。
- J.83 Annex Bは、`SYMBOL_RATE`があればその値で受けます。日本の光配信（5.6Msym/s）は`SYMBOL_RATE = 5600000`と書きます。`SYMBOL_RATE`が無いときは変調方式で決め、`MODULATION = QAM/64`なら5.057Msym/s、それ以外は5.361Msym/s（256QAM）です。

Annex Bで`BANDWIDTH_HZ`を書くと、復調器は無視しますが、チューナーはその値を使います。
Si2168はAnnex Bのとき帯域を6MHzにしますが、チューナーには定義ファイルの値をそのまま渡すので、`BANDWIDTH_HZ = 8000000`と書くとSi2141／Si2157のチャンネルフィルターが8MHzになります。
Annex Bでは`BANDWIDTH_HZ`を書かないか、6000000にしてください。

```ini
[UHF-EXAMPLE]
DELIVERY_SYSTEM = DVBT
FREQUENCY = 557142857
BANDWIDTH_HZ = 6000000

[CABLE-EXAMPLE]
DELIVERY_SYSTEM = DVBC/ANNEX_A
FREQUENCY = 450000000
SYMBOL_RATE = 5217000

[ANNEX-B-EXAMPLE]
DELIVERY_SYSTEM = DVBC/ANNEX_B
FREQUENCY = 453000000
MODULATION = QAM/256
```

## 信号測定

C/Nは、Si2168がロックの応答で返す1/4dB単位の値です。
信号強度は、Si2157／Si2141のコマンド`0x42`が返す符号付きの整数（dBm）です。
チューナー側で測った値なので、ロックしないチャンネルでも意味があります（何も無い周波数と、電波はあるのに受信できないチャンネルを見分けられます）。

## 制限事項

扱えるのはDVB-T/T2と、ITU-T J.83 Annex A/B/Cだけです。

## Windowsでベンダードライバーのまま使う

WinUSBに入れ替えず、MyGicaのベンダードライバーを入れたままでも、同じバックエンド`t230`として使えます。
チューナーの名前は`t230:<デバイスパスのハッシュ>:0`です。

ドライバーはキャプチャフィルターに、ボード上のI2Cバスへの転送を行うベンダープロパティを公開しています。
TSの転送はドライバーが行い、選局、ロック判定、信号測定は、このプロパティを通してcoaxがSi2168とチューナーを直接制御します。
チップはドライバーがファームウェアを読み込んだ状態で使うので、ファームウェアのファイルは要りません。
実機で確認したのはMyGica T230C2（`0572:c68a`）です。

ドライバー自身の選局では、ISDB-Cを受信できません。

- DVB-CとISDB-Cのネットワーク方式を受け付けません。
- DVB-Tの方式で変調にQAMを指定するとDVB-Cとして動きますが、シンボルレートをSi2168に設定しません。

そのため、グラフにはチャンネルを渡さず、チップへの設定はすべてcoaxが行います。
ドライバーにチャンネルを渡すと、グラフが動き始めた後にその選局が遅れて実行され、coaxの設定を上書きします。

BDAのグラフは`coaxd bda-host`のプロセスが持ちます（[bda.md](bda.md#グラフを持つプロセス)）。
このドライバーは、受信中にグラフを止めずにプロセスが終わると、そのプロセスが終われなくなり、チューナーを抜き差しするまで使えなくなります。
