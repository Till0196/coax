# Linux DVB API（バックエンド`dvb`）

| | |
| --- | --- |
| バックエンド | `dvb` |
| 対応OS | Linux専用 |
| 伝送方式 | カーネルドライバーが`DTV_ENUM_DELSYS`で申告するもの（ISDB-S3を除く。[下記](#対応する伝送方式)）|
| ファームウェア | `coaxd`には不要。必要ならカーネルのドライバーが書き込みます |

カーネルのDVBドライバーが`/dev/dvb`に公開しているフロントエンドを、そのドライバーを通して使います。
一覧と選局はドライバーが公開している情報だけを使い、デバイスごとの情報は持ちません。
そのため、LinuxのDVBドライバーがあるデバイスは、基本的にはこのバックエンドで使えます。

## このバックエンドで扱うデバイス

| カーネルドライバー | 対象ハードウェア | 同じ機器の別経路 |
| --- | --- | --- |
| `earth-pt3`（mainline）| Earthsoft PT3 | pt3ドライバー経由の`chardev`バックエンド（[chardev.md](chardev.md)）|
| `earth-pt1`（mainline）| Earthsoft PT1 / PT2 | pt1_drv経由の`chardev`バックエンド（[chardev.md](chardev.md)）|
| `ddbridge`（mainline）| Digital Devices製PCIeボード | Windowsでは`dd`バックエンド（[dd.md](dd.md)）|
| TBS配布の`linux_media`（`tbsecp3`ほか）| TurboSight製PCIeボード | Windowsでは`tbs`バックエンド（[tbs-pcie.md](tbs-pcie.md)）|
| TBS配布の`linux_media` | TBS 5520 / 5520SE / 5530（USB）| 直接USBの`tbs5520`ほか（[tbs.md](tbs.md)）|
| `smsusb`（mainline）| MyGica S270 / PLEX PX-S1UD | 直接USBの`s270`（[s270.md](s270.md)）|
| `dvb_usb_dvbsky`（mainline）| MyGica T230系 | 直接USBの`t230`（[t230.md](t230.md)）|
| その他のDVBドライバー | mainlineが対応するUSBドングル、PCIeボード全般 | - |

同じボードを2つの経路から同時に使うことはできません。
どちらか一方のドライバーだけを読み込んでください。
直接USBバックエンドで使いたいデバイスにカーネルのドライバーが当たっているときは、先にunbindするか、そのドライバーを読み込まないようにします（[os.md](../setup/os.md#カーネルドライバーからのunbind)）。

経路の選び方は[backends.md](../setup/backends.md#同じデバイスに複数の経路があるとき)にあります。
要点は次のとおりです。

- **`dvb`の利点**：ドライバーが導入済みであれば、追加の準備は不要です。ファームウェアのファイルも不要です（必要なデバイスではドライバーが書き込みます）。DVBv5のプロパティをほぼすべて渡せるので、階層伝送や符号化率まで書いた定義ファイルもそのまま使えます。
- **`dvb`の制約**：受信できる範囲も測定値もドライバーに依存します。ドライバーの申告が誤っていても、`coaxd`の側では回避できません（例は[`earth-pt3`がVHF/CATVを断る件](#earth-pt3が受け付ける周波数の範囲)）。APIにISDB-S3の番号が無く、内蔵カードリーダーも使用できません。

px4_drvや、PT1/PT2/PT3用のpt1_drv・pt3ドライバーは、DVBドライバーではありません。
これらが公開するのは`/dev/px4video*`などのキャラクタデバイスで、`/dev/dvb`には出ません。
これらのドライバーで使う場合は`chardev`バックエンドです（[chardev.md](chardev.md)）。

## 前提

カーネルのドライバーが入っていてモジュールが読み込まれていることと、`/dev/dvb/adapterN/`の下のノードを読み書きできることが必要です。
多くのディストリビューションではノードが`video`グループのものなので、`coaxd`を動かすユーザーがそのグループに入っていれば足ります（`id -nG`で確かめ、入っていなければ`sudo usermod -aG video $USER`をしてログインし直します）。

ノードが`/dev/dvb`に無い環境（コンテナなど）では、`coaxd`の`--dvb-root`で場所を指定します。

フロントエンドは1つのプロセスしか開けません。
使用中のフロントエンドを開こうとすると`EBUSY`が返ります。
USBインタフェースの排他と同じなので、DVBアダプターもUSBチューナーと同じように貸し出します（[tuner-host.md](../reference/tuner-host.md#プロセスモデル)）。

## 一覧と名前

`/dev/dvb`の下から`adapterN/frontendM`を探し、`dvb:adapter0.frontend0:0`のような名前で`/tuners`に並べます。
名前はシリアル番号ではなく、デバイスパスの位置から作ります。
アダプター番号はドライバーが読み込まれた順で決まるので、複数のボードを挿しているPCでは入れ替わることがあります。

このバックエンドは、ほかと違って、一覧を作るときにフロントエンドを一時的に開きます。
デバイスツリーには名前も伝送方式も書かれておらず、ioctlで問い合わせる必要があるためです。
問い合わせが終わればすぐに閉じます。

| 項目 | 読む所 |
| --- | --- |
| 製品名（`description`）| `FE_GET_INFO`の`name`。ドライバーが付けた名前です（例: `Sony CXD2856 DVB-T/T2/C demodulator`）|
| 受信できる伝送方式（`deliveries`）| `DTV_ENUM_DELSYS` |
| 周波数の範囲 | `FE_GET_INFO`の`frequency_min`／`frequency_max` |

使用中で開けなかったフロントエンドも、一覧から消しません。
前に開けたときに取得した内容をそのまま返します。
同じ場所に同じデバイスがある限り内容は変わらず、録画中にチューナーが一覧から消えると、クライアントがチューナーを見失うためです。

`deliveries`が空欄になるドライバーもあります。
`DTV_ENUM_DELSYS`に対応していない古いドライバーです。
空欄は「受信できない」ではなく「不明」という意味です。
方式を指定した要求でも候補に入り、受信できなければ選局のときに断られます。

方式名の綴りの違いは同じものとして扱い、一覧には両方の綴りを載せます。
`DVB-C`と`DVB-C/ANNEX_A`、`ISDB-C`と`DVB-C/ANNEX_C`は同じ方式です。
一覧を読む側は名前で照らし合わせるので、片方しか載せないと「受信できるのに対応していない」と判断されてしまいます。
Annex Bだけは別の方式なので、同じには扱いません。

`/tuners/{id}`には`mode`と`settings`も出ます。
`mode`はフロントエンドがいまどの伝送方式になっているか、`settings`はドライバーがいま持っている選局のパラメーターで、どちらも`dvbv5-fe-tool`が表示するものと同じです。
複数の方式に対応したフロントエンドは一度に1つの方式にしかなれないので、ロックしないときは、ここが目的の方式になっているかを見てください。

## 定義ファイル

共通の書式は[channel-files.md](../reference/channel-files.md)にあります。
このバックエンドは、すべてのバックエンドの中で最も多くのプロパティを受け付けます。
定義ファイルに書ける選局の項目は、すべてフロントエンドのDTVプロパティにそのまま渡します。

| 定義ファイルの項目 | 渡す先 |
| --- | --- |
| `DELIVERY_SYSTEM` | `DTV_DELIVERY_SYSTEM` |
| `FREQUENCY` | `DTV_FREQUENCY` |
| `BANDWIDTH_HZ` | `DTV_BANDWIDTH_HZ` |
| `SYMBOL_RATE` | `DTV_SYMBOL_RATE` |
| `STREAM_ID` | `DTV_STREAM_ID` |
| `MODULATION` | `DTV_MODULATION` |
| `INVERSION` | `DTV_INVERSION` |
| `INNER_FEC` | `DTV_INNER_FEC` |
| `CODE_RATE_HP`／`CODE_RATE_LP` | `DTV_CODE_RATE_HP`／`_LP` |
| `TRANSMISSION_MODE` | `DTV_TRANSMISSION_MODE` |
| `GUARD_INTERVAL` | `DTV_GUARD_INTERVAL` |
| `HIERARCHY` | `DTV_HIERARCHY` |
| `PILOT` | `DTV_PILOT` |
| `ROLLOFF` | `DTV_ROLLOFF` |
| `VOLTAGE`／`POLARIZATION` | `DTV_VOLTAGE`（[下記](#lnb給電偏波トーン)）|
| `TONE` | `DTV_TONE` |
| `SAT_NUMBER` | DiSEqCのioctl群（[下記](#diseqc)）|
| `GAIN`／`LNA` | `DTV_LNA`（[下記](#gainとlna)）|
| `LNB` | フロントエンドには渡さず、周波数の変換にだけ使う |

表に無い選局の項目を書くとエラーになります（黙って無視はしません）。
`SERVICE_ID`や`VIDEO_PID`のような選局に使わない項目は、`coaxd`に渡す前に捨て、捨てたことを知らせます（[tuner-host.md](../reference/tuner-host.md#クエリ文法)）。

### 対応する伝送方式

`DELIVERY_SYSTEM`は、カーネルの`SYS_*`の番号に直して渡します。
使える綴りは次のとおりです。

| 綴り | `SYS_*` |
| --- | --- |
| `DVB-C/ANNEX_A`（裸の`DVB-C`も同じ）| `SYS_DVBC_ANNEX_A` |
| `DVB-C/ANNEX_B` | `SYS_DVBC_ANNEX_B` |
| `DVB-C/ANNEX_C`、`ISDB-C` | `SYS_DVBC_ANNEX_C` |
| `DVB-C2` | `SYS_DVBC2` |
| `DVB-T`、`DVB-T2` | `SYS_DVBT`、`SYS_DVBT2` |
| `DVB-S`、`DVB-S2` | `SYS_DVBS`、`SYS_DVBS2` |
| `ISDB-T`、`ISDB-S` | `SYS_ISDBT`、`SYS_ISDBS` |
| `ATSC` | `SYS_ATSC` |

注意点が2つあります。

- **ISDB-Cは`SYS_DVBC_ANNEX_C`として送ります**：APIには`SYS_ISDBC`もありますが、カーネルのどのフロントエンドドライバーもこれに対応しておらず、DVBコアも「まだ対応ドライバーが無い」番号として扱っています。送っても、実際にISDB-Cを受信できるデバイスを含め、すべてのドライバーがエラーを返します。ISDB-CはITU-T J.83 Annex Cそのものなので、Annex Cとして選局するのが正しいやり方です。
- **APIにISDB-S3の番号がありません**：そのため、このバックエンドでは`DELIVERY_SYSTEM = ISDBS3`が使えません。高度BS/CSのチャンネルは、`DELIVERY_SYSTEM = ISDBS`のまま`STREAM_ID`にTLVストリームIDを書いてください。ISDB-SかISDB-S3かは復調器が見分けるので、Stream IDを書くだけで足ります（[channel-files.md](../reference/channel-files.md#isdb-s3の書き方)）。

## 周波数の範囲チェック

チューナーが受信できない周波数は、ドライバーを呼ぶ前に`coaxd`が断ります。
`/tune`は`unsupported`（`reason`は`out_of_range`）を返し、`coax scan`もそう記録します。
これは`no_lock`とは区別されます。
フロントエンドは、範囲外の場合も値が不正な場合も`FE_SET_PROPERTY`に同じ`EINVAL`を返し、原因を区別できないためです。
こうしておくと、帯域を通してスキャンしたときに、対応していない帯を「受信できなかった」ではなく「そのチューナーの範囲外」として記録できます。

範囲を申告しないドライバー（`frequency_max`が0）では、この確認をしません。

### 範囲の単位

フロントエンドが返す周波数の範囲は、そのとき設定されている伝送方式のもので、単位もその方式のものです。
衛星ならkHz、それ以外ならHzです。

衛星とケーブルの両方に対応したボードが衛星の方式のままだと、ケーブルの選局でも`45000..3224000`（kHz）を返します。
ケーブルのチャンネルはHzで書かれているので、定義ファイルのすべてのチャンネルが1000倍の値として範囲外になります。
「帯域がまるごと範囲外」という症状になり、単位の取り違えではなく定義ファイルの数字が間違っているように見えてしまいます。

そのため選局のたびに、まず`DTV_DELIVERY_SYSTEM`だけを設定してフロントエンドをその方式にし、それから範囲を読み直します。
読み直しに失敗しても、選局は続けます。
この確認は選局の前に分かりやすいエラーを返すためのもので、受信できるかを最終的に決めるのはフロントエンドだからです。

### `earth-pt3`が受け付ける周波数の範囲

ここまでの話が実際に問題になる例です。
`dvb`バックエンドでPT3を使うと、VHF 1〜12とCATV C13〜C63を選局できません。
PT3の能力ではなく、カーネルのドライバーの問題です。

カーネルの`earth-pt3`が扱うのは基板そのものだけで、選局はほかの2つのモジュールが行います。
PT3の地上波の系統は、復調器`tc90522`とチューナー`mxl301rf`の組み合わせで、どちらもカーネル本体に入っています。
この2つが、それぞれ受信できる周波数の範囲をDVBコアに申告します。

| カーネルのモジュール | 申告している範囲 |
| --- | --- |
| 復調器 `tc90522`（`drivers/media/dvb-frontends/tc90522.c`）| 470〜770 MHz |
| チューナー `mxl301rf`（`drivers/media/tuners/mxl301rf.c`）| 93〜803.142857 MHz |

DVBコアは2つの範囲が重なる部分を使うので、狭いほうの470〜770MHzになります。
つまり、チューナーは受信できる周波数でも、復調器の申告によって範囲外として扱われます。

前の節のとおり、この範囲を外れたチャンネルは`unsupported`（`reason`は`out_of_range`）になります。
帯域を通してスキャンすると、CATVパススルーの同軸でUHFだけが受かり、ミッドバンドが1波も出ない、という形で現れます。

カーネルの`tc90522`の申告をチューナーに合わせて広げれば、選局できるようになります。
パッチは[`tc90522-isdbt-band.patch`](../internals/tc90522-isdbt-band.patch)で、`.frequency_min_hz`を90MHz、`.frequency_max_hz`を806MHzに広げるだけです。
重なる部分を使うので、実際の範囲はチューナーの93〜803.142857MHzちょうどになります。
パッチを当ててビルドし直した`earth-pt3`で、`unsupported`が出なくなり、すべてのチャンネルで選局を試みるようになることを実機で確かめています。

VHFやCATVのパススルーを受信したいが、カーネルにパッチを当てたくない場合は、`chardev`でpt3ドライバー（[m-tsudo/pt3](https://github.com/m-tsudo/pt3)）を使ってください。
こちらはチャンネル番号のテーブルを持っているので、そのままVHFもCATVも受けられます。

## LNB給電、偏波、トーン

Linux DVB APIで出せる電圧は、13V、18V、OFFの3つだけです。
`VOLTAGE`の書き方との対応は次のとおりです。

| 書き方 | 送る値 |
| --- | --- |
| `VOLTAGE = low`（`11`、`13`）| `SEC_VOLTAGE_13` |
| `VOLTAGE = high`（`15`、`18`、`on`）| `SEC_VOLTAGE_18` |
| `VOLTAGE = off`（`0`、`none`）| `SEC_VOLTAGE_OFF` |

日本の124/128度CSは給電が11V／15Vですが、このAPIでは指定できません。
日本向けのボードか、電圧の変換器が必要です。
11V／15Vを実際に出せるのは、`chardev`バックエンドとWindowsの`pt3`／`pt1`だけです（[channel-files.md](../reference/channel-files.md#11v15vの扱い)）。

`VOLTAGE`の数字は、電圧の値そのものではなく、上の表のどの段かとして読みます。

`POLARIZATION`も、同じ`DTV_VOLTAGE`で送ります。

| 値 | 電圧 |
| --- | --- |
| `H`／`HORIZONTAL`、`L`／`LEFT`／`CIRCULAR_LEFT` | 18V |
| `V`／`VERTICAL`、`R`／`RIGHT`／`CIRCULAR_RIGHT` | 13V |
| `OFF` | 何も送りません（「偏波の指定が無い」という意味だからです）|

円偏波もそのまま使えます。
libdvbv5は4つの決まった単語しか受け付けず、それ以外の値があるとファイル全体を構文エラーにするので、円偏波を書いた定義ファイル（Cバンドや日本の衛星）を読めません。

`VOLTAGE`と`POLARIZATION`の優先順位には、決まりが2つあります。

- **`VOLTAGE = off`は`POLARIZATION`より優先します**：このAPIでは2つが同じプロパティになり、`POLARIZATION`のほうが後に送られるので、そのままでは偏波の電圧で上書きされます。給電しないと書いたチャンネルで給電されないように、このときは偏波を送りません。それ以外のときは逆で、偏波が優先します。
- **衛星のチャンネルに電圧も偏波も書かれていなければ、`SEC_VOLTAGE_OFF`を明示的に送ります**：何も送らないのではありません。フロントエンドは前の選局で出した電圧を保持するので、何も送らないと前のチャンネルの給電を引き継いでしまうためです。既定を「給電しない」にしている理由は[channel-files.md](../reference/channel-files.md#voltage)にあります。

`TONE`は`DTV_TONE`にそのまま渡します。
バンドの切り替えが要るLNBf（`UNIVERSAL`など）では、切り替え周波数以上で自動的にトーンを出しますが、チャンネルに`TONE`が書いてあればそちらを優先します。

## DiSEqC

`SAT_NUMBER`を書いたチャンネルでは、選局の前に、DiSEqC 1.0のスイッチ切り替えコマンドを同軸に送ります。
コマンドの相手は同軸の先にあるスイッチで、選局の相手の復調器とは別だからです。
コマンドを送るまで、スイッチは前のチャンネルで選んだ入力のままです。

このAPIでは、電圧、トーン、メッセージがそれぞれ別のioctlなので、規格が決めている順序と間隔で`coaxd`が送ります。
BDAではバイト列をドライバーに渡して終わりですが、こちらはすべての段を`coaxd`が制御します。

| 順 | 操作 |
| --- | --- |
| 1 | `FE_SET_TONE`でトーンを止める（メッセージ自体がトーンのオンオフで送られるので、送る間は止めておく）|
| 2 | `FE_SET_VOLTAGE`で電圧を上げる（スイッチは同軸の電気で動くので、送る前に電圧が上がって落ち着いている必要がある）|
| 3 | 15 ms待つ |
| 4 | `FE_DISEQC_SEND_MASTER_CMD`でメッセージを送る |
| 5 | 15 ms待つ |
| 6 | `FE_DISEQC_SEND_BURST`でトーンバーストを送る（トーンバーストにしか対応していない古いスイッチのため）|
| 7 | 15 ms待つ |
| 8 | `FE_SET_TONE`でチャンネルが要求したトーンにする |

15msは規格が決めている間隔で、スイッチもこの間隔を前提に作られています。

トーンバーストを送るのが、Windows BDAとの違いです。
BDAでは送りません。
BDAにはこの順序を制御する手段が無く、ドライバーが1回でメッセージとバーストの両方を送ると、スイッチが別々の2つの指示を受け取ってしまうためです（[dvb-s2.md](../scanner/dvb-s2.md#diseqcスイッチ)）。

## `GAIN`と`LNA`

`DTV_LNA`に渡します。
`min`が0（切）、`max`が1（入）、`auto`が`LNA_AUTO`です。

dBでは指定できません。
このAPIには入、切、自動の3つしかないためです。
`+13dB`のように書くとエラーになります。

このバックエンドだけは、増幅器を持たないフロントエンドに指定してもエラーになりません。
そのようなドライバーはこのプロパティを無視し、選局は成功します。
増幅器の有無はカーネルのドライバーしか持っていない情報なので、`coaxd`では判断できません。
ほかのバックエンドでは、設定を持たないチューナーへの指定はエラーで断ります（[channel-files.md](../reference/channel-files.md#gainとlna)）。

`GAIN`と`LNA`は同じ設定なので、両方書くとエラーです。

## 信号測定

`DTV_STAT_CNR`と`DTV_STAT_SIGNAL_STRENGTH`を読みます。
値はAPIの1/1000dB単位から直します。

使うのは`FE_SCALE_DECIBEL`で返された値だけです。
ドライバーが相対値（`FE_SCALE_RELATIVE`、0〜65535の割合）を返したときは、値を捨てて「測定なし」にします。
単位の無い数字をdBやdBmとして見せると、実際とは違う値を表示することになるためです。
統計が無効（長さ0）のときも同じです。

測定に失敗しても、ロックの判断には影響しません。
値が出ないだけです。
測定に対応していないフロントエンドは多く、ロックしているのにエラーと判断しないためです。

そのため、このバックエンドでC/Nや信号強度が出るかどうかは、ドライバーに依存します。
`FE_SCALE_DECIBEL`で値を返すドライバーなら両方出て、返さないドライバーでは何も出ません。

## ストリームの取り出し

`demuxN`に、PID `0x2000`（すべてのPID）のPESフィルターを`DMX_OUT_TS_TAP`ですぐ始まるように設定し、`dvrN`から読みます。
フィルターの設定と`dvrN`を開くのはストリームを流すときだけで、選局や信号測定では行いません。

`dvrN`は`O_NONBLOCK`で開き、`EAGAIN`は「まだ届いていない」として扱います。
ストリームを閉じるときは、`DMX_STOP`を送ってからノードを閉じます。

## 制限事項

- **使える伝送方式、周波数の範囲、測定値は、すべてカーネルのドライバーに依存します**：ドライバーの申告が実際のハードウェアより狭くても、`coaxd`の側では回避できません（例は[`earth-pt3`がVHF/CATVを断る件](#earth-pt3が受け付ける周波数の範囲)で、これはカーネルへのパッチで直します）。
- `ISDBS3`は使えません。`ISDBS`と`STREAM_ID`で書いてください。
- LNB給電は13V／18V／OFFだけです。日本の124/128度CSに要る11V／15Vは出せません。
- `GAIN`はdBで指定できません。
- カードスロットを内蔵したチューナーでも、カードリーダーは使えません。カードへの経路がドライバーの中で閉じているためです（[card-reader.md](../reference/card-reader.md#搭載デバイス)）。
- Linux専用です。
