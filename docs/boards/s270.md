# MyGica S270 / PLEX PX-S1UD（バックエンド`s270`）

| | |
| --- | --- |
| バックエンド | `s270` |
| 対応OS | Linux / Windows / macOS（直接USB）|
| 伝送方式 | ISDB-T、DVB-T |
| ファームウェア | 要（`isdbt_rio.inp`／`dvb_rio.inp`。[firmware.md](../setup/firmware.md)）|

Siano Rio（SMS1xxx）を載せたスティックを直接制御します。
復調器やチューナーICをI2Cで個別に操作するのではなく、チップ上で動くファームウェアとメッセージをやり取りして選局します。
そのため`internal/coaxd/demod`と`internal/coaxd/tuner`にはドライバーが無く、メッセージのプロトコルは`internal/coaxd/usb/bridge/siano`、製品ごとの設定は`internal/coaxd/usb/board/s270`にあります。

各OSの前提は[os.md](../setup/os.md)にあります。
Linuxではカーネルの`smsusb`がこのデバイスにバインドされるので、先にunbindするか、`smsusb`を読み込まないようにしてください。

## 対応製品

| 製品 | VID:PID | チューナー本数 | 伝送方式 |
| --- | --- | --- | --- |
| MyGica S270 | `187f:0600`、`187f:0601` | 1 | ISDB-T、DVB-T |
| PLEX PX-S1UD | `3275:0080` | 1 | ISDB-T、DVB-T |

どちらも同じチップを使ったOEM製品で、coaxでは同じバックエンドで扱います。

## ファームウェア

伝送方式ごとに別のファームウェアが要ります。
ISDB-Tは`isdbt_rio.inp`、DVB-Tは`dvb_rio.inp`です。
入手先と置き場所は[firmware.md](../setup/firmware.md)にあります。
`isdbt_rio.inp`は、coaxが使うファームウェアの中で唯一カーネル公式のlinux-firmwareに入っています。
`dvb_rio.inp`はコミュニティのファームウェア集から入手します。

チップが一度に保持できるファームウェアは1つです。
選局する伝送方式に合わせて、必要になったときに書き込みます。
ISDB-TとDVB-Tを行き来するたびに書き直すので、両方が混ざった定義ファイルでは選局に時間がかかります。

## 定義ファイル

共通の書式は[channel-files.md](../reference/channel-files.md)にあります。
ここは`s270`固有の分だけを書きます。

- `DELIVERY_SYSTEM = ISDBT`ではフルセグ（13セグメント）で受信し、`STREAM_ID`と`BANDWIDTH_HZ`は使いません。
- `DELIVERY_SYSTEM = DVBT`では`BANDWIDTH_HZ`が必須で、6000000、7000000、8000000のどれかを書きます。ファームウェアが帯域を推測しないので、省略したり他の値を書いたりするとエラーになります。

チップはすべてのPIDを含むTSをそのまま出すので、スキャンではPAT、NIT、SDTをいつもどおり読めます。

## 信号測定

C/Nと信号強度は報告しません。
ファームウェアへ`MSG_SMS_GET_STATISTICS_REQ`（ISDB-Tは`_EX`）を送って統計を読みますが、使うのは`is_demod_locked`だけです。
他の項目は、値の尺度を確かめられていないためです。

## 制限事項

- DVB-Tは実機で確かめていません。選局は`MSG_SMS_RF_TUNE_REQ`（周波数、帯域コード、12MHz基準の3ワード）、ロックは`struct sms_stats`の`is_demod_locked`から読みます。拡張統計（`_EX`）はISDB-T専用です。
