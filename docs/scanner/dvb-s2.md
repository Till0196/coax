# DVB-S2

DVB-S2の放送（東経124度と128度のCS）は、地上波やBSのようにチャンネル番号だけでは選局できません。
伝送方式、ダウンリンク周波数、LNBf、シンボルレート、変調、偏波の6つが要ります。
この文書では、それらの指定のしかたと、DiSEqCスイッチの使い方をまとめます。

```sh
# 全項目を指定する場合
./coax tune --system DVBS2 --freq 12268000 --lnbf JCSAT3A -P SYMBOL_RATE=23303000 -P MODULATION=PSK/8 -P POLARIZATION=VERTICAL > dvb-s2.ts

# トランスポンダ名で指定する場合（公表されている周波数表から諸元が決まります）
./coax tune --ch JCSAT3A/JD5 > dvb-s2.ts

# 定義ファイルのセクション名で指定する場合
./coax tune --channels ~/dvb-s2.conf --ch JCSAT3A/JD5 > dvb-s2.ts
```

## トランスポンダ名で指定する

`--ch JCSAT3A/JD5`のように書くと、公表されている周波数表（JCSAT-3A号とJCSAT-4B号の周波数表）から選局のパラメーターが決まります。

| 系列 | ダウンリンク中心 | 帯域幅 | 本数 |
| --- | --- | --- | --- |
| `JCSAT3A/JD1`〜`JD16` | 12508 MHz から15 MHz間隔 | 27 MHz | 16 |
| `JCSAT3A/JD17`〜`JD28` | 12268 MHz から20 MHz間隔 | 36 MHz | 12 |
| `JCSAT4B/K1`〜`K16` | 12268.25 MHz から15 MHz間隔 | 27 MHz | 16 |
| `JCSAT4B/JD1`〜`JD16` | 12508.25 MHz から15 MHz間隔 | 27 MHz | 16 |

JCSAT-4Bは0.25 MHzずれているので、同じ番号付けの2つの衛星を周波数で見分けられます。
偏波は番号の偶奇で決まり、奇数が垂直、偶数が水平です（どちらの衛星、どちらの系列も同じ）。

書き出す周波数はダウンリンク周波数です。
中間周波数はトランスポンダが持つ値ではなく、局部発振器で周波数を下げたあとの値なので、設備によって変わります。
公表されている周波数表も、局発11.2 GHz用と10.678 GHz用の2列（差は522 MHz）を載せています。
1つのテーブルでどちらの設備にも対応するため、ダウンリンク周波数を保持し、LNBfを名前で指定して変換します。

同じ周波数に、2つの世代の方式が使われています。

| | 伝送方式 | 変調 | シンボルレート |
| --- | --- | --- | --- |
| 現行 | DVB-S2 | 8PSK | 23.303 Msym/s |
| 旧 | DVB-S | QPSK | 21.096 Msym/s |

23.3037 Msym/sは、27 MHzの中継器で占有周波数帯幅がちょうど27 MHzになる値で、現行のサービスはこれを使います。
旧方式（DVB-S、QPSK、21.096 Msym/s）のままのトランスポンダもあるので、どちらか一方だけを試すスキャンでは、もう一方を「何も載っていない」として見落とします。
そのため`--discover`は、60本のトランスポンダすべてを両方の方式で試します（120回）。

この中で、復調器が判別できないのはシンボルレートだけです。
DVB-S2の変調方式と内符号はフレームヘッダーに載っているので、指定していません。
指定しても受信は改善せず、誤った値ではロックしなくなります。

トランスポンダ名で旧方式を指すときは、`/QPSK`を付けます（`--ch JCSAT3A/JD9/QPSK`）。
スキャン結果にもこの名前で出るので、スキャン結果から作ったチャンネル一覧はそのまま選局に使えます。
実際に測ったシンボルレートがある場合は、定義ファイル（`--channels`）に書くか、`-P SYMBOL_RATE=`で上書きしてください。

## 衛星の選択と22kHzトーン

128度（JCSAT-3A）と124度（JCSAT-4B）は、同じアンテナ、同じ同軸、同じ局発で受けます。
`lnbf.go`にあるとおり局発はどちらも11200 MHzで、違うのは22kHzトーンの有無だけです。
そのため、周波数だけでは衛星が決まりません。

- `--lnbf JCSAT3A`か`--lnbf JCSAT4B`とダウンリンク周波数を渡すと、中間周波数への変換と一緒に`TONE`も決まります
- `--ch JCSAT3A/JD5`のようにトランスポンダ名で指定すると、名前からLNBfが決まり、変換のときに`TONE`も決まります。`--lnbf`を書いた場合はそちらが優先です
- `-P TONE=...`を書いた場合は、それが何よりも優先です（DiSEqCスイッチを挟んでいるなど、coaxが把握できない構成があり得るため）

エクスポートでは、DVB-S2のチャンネルに既定で`commandVars.satellite`を書き出します。
`route`と同じく、信号から判別できない項目のためです。

```yaml
- name: "テストチャンネル1"
  type: SKY
  channel: "JCSAT3A/JD5"
  route: SAT
  commandVars:
    satellite: JCSAT3A
```

トップレベルの`satellite:`ではなく、`commandVars`に入れます。
Mirakurunの`api.d.ts:399`が、4.0.0以降はトップレベルの`satellite`を非推奨とし、`commandVars`を使うよう求めているためです。
どちらに書いても行き先は同じで（`Channel.ts:356`がトップレベルの値を`commandVars`へまとめます）、`tuners.yml`の側では`<satellite>`でも、古い綴りの`<satelite>`でも読めます（`TunerDevice.ts:354`が`commandVars.satellite`から補います）。

## DiSEqCスイッチ

アンテナがスイッチを挟んで繋がっている場合は、`--sat-number`（定義ファイルなら`SAT_NUMBER`）でポートを指定します。
値は0〜3で、指定しなければスイッチには何も送りません。

```sh
./coax tune --channels ~/dvb-s2.conf --ch JCSAT3A/JD5 --sat-number 1
```

送るのはDiSEqC 1.0のcommitted switchコマンド（`E0 10 38 Fx`）です。
最後のバイトの下位ビットに、ポート番号と、トーンで選ぶバンドと、電圧で選ぶ偏波が入ります。

Linux DVBとWindows BDAのどちらでも使えますが、送信の仕組みが異なります。

| | Linux DVB | Windows BDA |
| --- | --- | --- |
| 経路 | `FE_SET_TONE` / `FE_SET_VOLTAGE` / `FE_DISEQC_SEND_MASTER_CMD` / `FE_DISEQC_SEND_BURST` | `IBDA_DiseqCommand`（トポロジのコントロールノード）|
| 順序と待ち | coaxが決める（トーンOFF→電圧→15ms→メッセージ→15ms→バースト→15ms→トーン）| ドライバーが決める。coaxはバイト列を渡すだけ |
| 電圧、トーン | 明示的に設定 | チューニングスペースのLNB情報からドライバーが決める |
| バースト | 送る | 送らない（`put_DiseqUseToneBurst(0)`）|

BDAでバーストを送らないのは、ドライバーが1回のやり取りでメッセージとバーストの両方を出すと、スイッチが2つの違う指示を受け取ってしまうためです。
BDAには同軸の電圧やトーンを直接操作する手段がなく（BDAのチューナーで給電を切れないのと同じ理由です）、coaxにできるのはメッセージを渡すことだけです。

`IBDA_DiseqCommand`のノードを公開しないドライバーもあります。
その場合に`SAT_NUMBER`を指定するとエラーになります。
無視すると、スイッチが切り替わらないまま別の衛星を受信し続けるためです。

`IBDA_DiseqCommand`はksproxyがKSプロパティセット（GUIDはインタフェースIIDと同じ`F84E2AB0-…`）に変換してドライバーへ渡します。
どのプロパティを実装しているかは、ドライバーによって違います。

| プロパティ | TBS 6903 / 6812 | Digital Devices |
| --- | --- | --- |
| 0 ENABLE | ○ | ○ |
| 1 LNB_SOURCE | ○ | ○ |
| 2 USETONEBURST | ○ | × |
| 3 REPEATS | ○ | × |
| 4 SEND | ○（設定のみ）| ○（設定のみ）|
| 5 RESPONSE | ○（取得のみ）| × |

TBSは、DVB-S2X製品（6903のx64版とx86版、新旧どちらのバージョンも）でも6812でも6つすべてを実装しています。
Digital Devicesは3つだけです。

そのため、coaxが必ず使うのはENABLEとSENDだけで、バーストと繰り返し回数は設定できるときだけ設定します。
どちらも、無いときの既定は「バースト無し、繰り返し無し」で、設定したい値と同じです。
無いことを失敗として扱うと、Digital Devicesではメッセージが1つも送られなくなります。

送信後は待機します。
`put_DiseqSendCommand`は送信を終えてから戻るのではなく、メッセージをキューに入れて送信用のスレッドを起こしたところで戻ります。
完了を待つ手段がインタフェースに無いので、メッセージが同軸に出るのにかかる時間だけ待ってから選局します。
DiSEqCの1バイトは、22kHzのキーイングで約13.5msです。

メッセージの長さを3〜8バイトに制限しているドライバーもあります（範囲外は`STATUS_INVALID_PARAMETER`）。
coaxが送るcommitted switchコマンドは4バイトなので、この範囲に収まります。
